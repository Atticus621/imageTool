# 网络交互系统架构

## 总体架构

```
外部脚本 ──HTTP/WS──→ uvicorn(后台线程) ──Signal──→ Qt主线程
                                                  ↓
                                              执行操作
                                                  ↓
                                          Signal返回结果 → HTTP/WS响应
```

## 核心设计

### 1. Signal桥接器（bridge.py）
网络线程不直接调用UI，通过Signal发送命令，Qt主线程处理后Signal返回结果。

```python
class NetworkBridge(QObject):
    # 网络→主线程
    command_received = Signal(dict)     # {"action": "create_node", "params": {...}}
    # 主线程→网络
    result_ready = Signal(str, dict)    # (request_id, result)
```

### 2. 全局错误总线（error/bus.py）
所有模块通过同一总线报告错误。

```python
class ErrorBus(QObject):
    error_occurred = Signal(str, str, dict)  # (code, message, details)
```

UI连接它显示弹窗，日志连接它写文件，API连接它返回错误响应。

### 3. API路由自动发现
`api/router.py` 自动扫描 `api/v1/` 下所有模块，注册路由。新增API只需在 `v1/` 下加文件。

### 4. Qt事件模拟器（input/simulator.py）
```python
class InputSimulator(QObject):
    def simulate_click(self, x, y, button="left"):
        # 使用 QTest.mouseClick 或 QCursor + QMouseEvent
    def simulate_key(self, key):
        # 使用 QTest.keyClick
```

## API示例

| 方法 | 路径 | 功能 |
|---|---|---|
| POST | /api/v1/nodes | 创建节点 |
| DELETE | /api/v1/nodes/{id} | 删除节点 |
| GET | /api/v1/nodes | 列出所有节点 |
| POST | /api/v1/nodes/{id}/params | 设置参数 |
| POST | /api/v1/graph/connect | 连接两个端口 |
| POST | /api/v1/graph/run | 执行 |
| POST | /api/v1/graph/stop | 停止 |
| GET | /api/v1/system/status | 系统状态 |
| GET | /api/v1/system/errors | 最近错误 |
| POST | /api/v1/input/click | 模拟鼠标点击 |
| POST | /api/v1/input/key | 模拟键盘输入 |
| WS | /ws/events | 实时事件流 |

## 需要修改的现有文件

| 文件 | 变更 |
|---|---|
| `ui/main_window.py` | 连接ErrorBus信号显示错误，连接NetworkBridge处理命令 |
| `main.py` | 启动网络服务任务 |
| `config/app.yaml` | 新增network配置（端口等） |
